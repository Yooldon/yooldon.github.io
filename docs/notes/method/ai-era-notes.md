# AI 时代该记什么

收藏和囤积确实没意义了——任何定义、教程、参数表，问一句就有，而且比我的摘录更准。
但「不用记」和「该记什么」是两件事。这篇是我的判断标准。

## 一个判据

> 六个月后，这段内容我还能不能重新拿到？
>
> 能（网上有、AI 一秒能生成）→ 只留指针，不留全文。
> 不能（当时的判断、现场的报错、某人的口头决定）→ 记全文。

再叠一层筛子：**「AI 能不能替我写出来？」能 → 不记；不能 → 记。**

## 值得记的五类

| 类型 | 内容 | 为什么 AI 替不了 |
| --- | --- | --- |
| 决策 | 背景、备选、选了哪个、排除了什么 | 它不知道我的约束和代价函数 |
| 踩坑 | 报错原文、错误假设、排查路径 | 现场证据不可再生 |
| 问题 | 还没想明白、悬着没解的 | 好问题比好答案稀缺 |
| 半成品 | 脚本、提示词、模板、可用片段 | 有我的调试痕迹和使用语境 |
| 上下文 | 团队习惯、领域术语、项目历史 | 不在任何公开语料里 |

它们的共同点：**都不是「知识」，是「关于我的数据」。** 知识可以外包，关于我的数据不能。

## 不值得记的

- 定义、概念解释、教科书结论
- API 参数表、教程步骤（官方文档更新比你快）
- 别人的观点摘录、书摘金句
- 方法论框架、思维模型清单
- 任何「读完觉得有道理」但没改变我行为的东西

::: tip 指针仍然要留
不收藏内容，但要收藏**入口**：谁说的、在哪、什么时候。像书目一样，只存线索不存正文。
:::

## 模板

```yaml
---
type: decision | failure | question | artifact
status: open | settled | stale
date: 2026-11-19
project: 项目名
source: 链接（事实类才填）
verified: yes/no   # AI 参与过就必须标
---
```

```markdown
## 情境（当时的约束是什么）
## 我做了什么 / 我的判断
## 为什么（排除了哪些选项，代价是什么）
## 结果（到期回填）
## 如果重来
```

关键在最后两栏。**结果要到期回填，「如果重来」要真的写**——没有复盘的决策记录，
只是换了个姿势的囤积。

## AI 内容进库的规矩

::: warning 原样存是会有毒的
- 污染检索：搜到的是模型的措辞，不是我的。
- 稀释信号：库里大半是正确但无用的通稿。
- 制造幻觉：读起来太顺，大脑就跳过验证。
:::

规矩只有一条：**AI 产出进草稿区，经我改写或验证才能进主库，并标注 `verified`。**
一条全是 AI 写的笔记，价值约等于零——那只是把搜索成本换成了存储成本。

## 每周流程

| 频率 | 动作 | 目的 |
| --- | --- | --- |
| 随时 | 只记「我的」东西，进 Inbox | 捕捉摩擦要接近零 |
| 每周 | 清空 Inbox：删掉一半，剩下的改写 | 库才会变锋利 |
| 每月 | 挑一篇回填「结果」，验证旧判断 | 让笔记有反馈 |
| 每季 | 删掉 20% 能重新生成的内容 | 删除是维护，不是损失 |

## 判断标准

> 过去 30 天，我从库里取出东西并用了多少次？

接近 0 的话，问题不在记法，在于没有「用」的场景。先把场景找出来，笔记会自己长对。
