# 像文档一样写笔记

DeepSeek 的 API 文档是个很好的模板：它不靠文采，靠**位置**——读者永远知道自己在哪、
下一步该看什么。这篇拆它的结构，并给出移植到个人笔记的做法。

## 三栏各管一件事

| 区位 | 承担什么 | 写作要求 |
| --- | --- | --- |
| 左上 · 一级分类 | 我在哪一类知识里 | 按「能力/主题」分，不按文件类型分 |
| 左侧 · 分页目录 | 这一类里有哪些页 | 当前页高亮，层级不超过三层 |
| 中间 · 正文 | 这一页回答什么 | 一页只回答一个问题 |
| 右侧 · 本页目录 | 这一页讲到第几点 | 从 H2/H3 自动生成，可锚点分享 |

左栏和右栏不是重复：左栏管**跨页**定位，右栏管**页内**定位，是两条正交的轴。

## 正文的四段式

```text
H1        主题词（不做标题党）
摘要       一句话：是什么 + 为什么，读完就能决定要不要继续
H2 动宾    标题即任务（"开关与强度控制"，不是"参数说明"）
  表格     行 = 决策维度，列 = 方案/协议
  脚注     默认值、例外、映射规则，下沉
  例子     最小可运行代码
```

顺序不能换。先给心智模型，再给对照，再给边界，最后给可执行的东西——读者会在任意一层停下，
所以每一层都必须自足。

## 表格什么时候该出场

出现两个及以上维度就该用表，典型是「同一件事的多种写法」：

| 场景 | 用表 | 用段落 |
| --- | --- | --- |
| 三种协议传同一个参数 | ✅ 一行扫完 | ❌ 要读三段才知道区别 |
| 一个概念的来龙去脉 | ❌ 因果链会被切碎 | ✅ 顺着读 |
| 参数默认值与取值 | ✅ 可查 | ❌ 埋在句子里找不到 |

一个细节：官方文档那张表里，`{"thinking": ...}` 那格**横跨两列**，因为它对 OpenAI 和
Anthropic 两种格式是同一个写法。合并单元格不只是排版，它在声明「这两个东西等价」。

## 把例外沉到脚注

正文只留主干，默认值、坑、版本差异放进提示块：

::: warning 默认值
思考模式默认打开，`effort` 默认 `high`。不写就等于开了最强推理，成本会悄悄变高。
:::

这样做的好处是：**复习时读主干，出问题时查提示块**，两种读法互不干扰。

## 移植到个人笔记的差别

文档写「是什么」，笔记还要多两段：

1. **我的判断**——官方说默认是 `high`，但它不说你该不该用 `high`。
2. **我的现场**——报错原文、错误假设、最后怎么定位的。这部分不可再生。

所以一篇个人笔记的完整骨架是：

```text
一句话定义 → 对照表 → 默认值与坑 → 最小例子 → 我的判断 → 出处与日期
```

## 反例

::: danger 别这样写
- 标题写成「学习笔记 3」「随手记」——三个月后你自己都搜不到。
- 一页塞五个主题——右栏目录会变成一锅粥，锚点失去意义。
- 通篇段落没有表格——凡是有对照关系的地方都在浪费读者的工作记忆。
:::

## 检查清单

写完一篇，问四个问题：

- [ ] 这一页只回答一个问题吗？
- [ ] 摘要那句话，能不能让人立刻决定读不读？
- [ ] 有对照关系的地方，是不是表格？
- [ ] 有没有一段是「只有我能写」的？

最后一题答不上来，这篇大概可以删。
